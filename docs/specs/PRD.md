## 1. 제품 개요

### 1.1 비전

"진짜 매니아만 알아보는, 진짜들을 위한 리뷰 플랫폼"

야미로그는 특정 영역의 깊은 취향을 가진 매니아들이 서로의 리뷰를 신뢰하고 발견할 수 있는 전문 리뷰 플랫폼이다. 일반 대중의 별점이 아닌, 검증된 매니아의 평가만이 노출되는 큐레이션 구조를 핵심으로 한다.

### 1.2 문제 정의

| 문제 | 현재 상황 | 기대 해결 |
|------|-----------|-----------|
| 매니아-일반인 평점 혼재 | 네이버/카카오 지도에 취향이 다른 사용자의 평점이 뒤섞임 | 동일 매니아 등급 이상의 리뷰만 노출 |
| 장르별 전문 리뷰 부재 | 필터 커피의 산미, 위스키의 캐스크 등 전문 항목 평가 불가 | 카테고리별 맞춤 평가 항목 |
| 매니아 검증 수단 없음 | 누구나 리뷰 작성 가능, 신뢰도 낮음 | 리뷰 수·퀄리티 기반 레벨 시스템 자동 부여 |
| 매니아 커뮤니티 부재 | 취향이 같은 사람을 찾고 팔로우할 채널 없음 | 카테고리별 매니아 피드 및 큐레이션 |

### 1.3 타깃 사용자

**Primary**: 특정 분야(커피·위스키·와인 등)에 깊은 관심을 가진 매니아 (20–45세)
**Secondary**: 매니아의 추천을 신뢰하고 싶은 입문자
**Tertiary**: 자신의 매장을 매니아에게 알리고 싶은 소규모 업장 운영자

## 2. 핵심 개념

### 2.1 카테고리 (Category)

MVP 출시 카테고리: **커피 / 위스키 / 와인**
각 카테고리는 독립적인 평가 항목(스키마)을 보유한다.

| 카테고리 | 주요 평가 항목 |
|----------|---------------|
| 필터 커피 | 원산지, 로스팅 프로파일, 추출 방식, 산미·바디·향 |
| 위스키 | 증류소, 숙성 연도, 캐스크 타입, 피트·달콤함·스파이시 |
| 와인 | 생산 지역, 빈티지, 품종, 타닌·산도·과실향 |

### 2.2 레벨 시스템 (Mania Level)

매니아 등급은 자동으로 산정된다. 수동 신청이나 관리자 승인 없이 활동 기반으로 부여된다.

| 레벨 | 명칭 | 조건 |
|------|------|------|
| 0 | 입문자 (Newbie) | 가입 후 기본 |
| 1 | 애호가 (Enthusiast) | 리뷰 5건 이상, 평균 퀄리티 점수 60+ |
| 2 | 매니아 (Mania) | 리뷰 20건 이상, 평균 퀄리티 점수 75+ |
| 3 | 전문가 (Expert) | 리뷰 50건 이상, 평균 퀄리티 점수 85+, 다른 사용자 추천 10건+ |
| 4 | 마스터 (Master) | 리뷰 100건 이상, 평균 퀄리티 점수 90+, 커뮤니티 공인 |

**퀄리티 점수 산정 기준**: 리뷰 길이(30%), 항목 작성 완성도(30%), 타 사용자 유용성 투표(40%)

### 2.3 리뷰 가시성 (Review Visibility)

리뷰 작성 시 최소 공개 레벨을 설정한다.

- **전체 공개**: 모든 사용자 열람 가능
- **매니아 이상**: Mania(2) 이상만 열람 가능
- **전문가 이상**: Expert(3) 이상만 열람 가능

## 3. 기능 명세

### 3.1 사용자 관리 (user-service)

#### 3.1.1 회원가입 / 로그인

| 항목 | 내용 |
|------|------|
| 지원 방식 | 소셜 로그인(Google, Apple, Kakao), 이메일 회원가입 |
| 프로필 구성 | 닉네임, 프로필 이미지, 주 관심 카테고리(복수 선택), 자기소개 |
| 레벨 표시 | 프로필에 카테고리별 레벨 뱃지 표시 |

#### 3.1.2 팔로우 / 팔로워

- 다른 사용자 팔로우 가능
- 팔로우한 사용자의 최신 리뷰가 피드에 노출

#### 3.1.3 레벨 이력

- 레벨 변경 이력 조회
- 현재 레벨 기준 다음 레벨 달성 조건 진행률 표시

---

### 3.2 카테고리 관리 (category-service)

#### 3.2.1 카테고리 조회

- 전체 카테고리 목록 조회
- 카테고리별 평가 항목 스키마 조회

#### 3.2.2 카테고리 확장 (Post-MVP)

- 관리자가 신규 카테고리 추가 가능
- 카테고리별 평가 항목 커스터마이징

---

### 3.3 장소 관리 (place-service)

#### 3.3.1 장소 등록

| 항목 | 내용 |
|------|------|
| 기본 정보 | 이름, 주소(카카오/네이버 지도 API 연동), 카테고리, 영업시간 |
| 등록 자격 | Enthusiast(1) 이상 |
| 중복 방지 | 동일 좌표 반경 50m 내 동일 카테고리 장소 중복 등록 경고 |

#### 3.3.2 장소 검색

- 키워드 검색 (장소명, 지역명)
- 위치 기반 반경 검색 (현재 위치 기준 N km 이내)
- 필터: 카테고리, 최소 레벨 평점 존재 여부, 영업 중 여부
- 정렬: 거리순, 매니아 평점순, 최신 리뷰순

#### 3.3.3 장소 상세

- 기본 정보 + 위치 지도
- 카테고리별 평균 점수 (전체 / 매니아 이상 / 전문가 이상 분리 표시)
- 리뷰 목록 (가시성 필터 적용)

---

### 3.4 리뷰 관리 (review-service)

#### 3.4.1 리뷰 작성

| 항목 | 내용 |
|------|------|
| 작성 자격 | Newbie(0) 이상 (단, 매니아 공개 리뷰는 Mania 이상) |
| 공통 항목 | 종합 점수(1–10), 방문일, 텍스트 리뷰, 이미지(최대 5장), 공개 레벨 설정 |
| 카테고리별 항목 | 카테고리 스키마에 따른 세부 평가 항목 |
| 동일 장소 재방문 | 재방문 리뷰 허용, 방문 기록으로 관리 |

#### 3.4.2 리뷰 조회

- 장소별 리뷰 목록 (접근자 레벨 기준 가시성 필터 자동 적용)
- 내 리뷰 목록
- 유용성 투표 (helpful / not helpful)

#### 3.4.3 리뷰 신고

- 스팸, 허위 정보, 부적절한 내용 신고
- 신고 누적 시 자동 블라인드 처리 (임계값: 5건)

---

### 3.5 피드 (feed-service)

#### 3.5.1 팔로우 피드

- 팔로우한 사용자의 최신 리뷰 시간순 노출
- 접근자 레벨 기준 가시성 필터 적용

#### 3.5.2 카테고리 피드

- 카테고리별 인기 리뷰 (최근 7일 유용성 투표 상위)
- 카테고리별 신규 장소
- 매니아 추천 픽 (Expert 이상이 작성한 리뷰 중 유용성 높은 것)

#### 3.5.3 탐색 피드

- 위치 기반 근처 매니아 리뷰
- "이 사람의 취향이 맞다면" — 유사 취향 사용자 추천 (Post-MVP, AI 기반)

---

### 3.6 레벨 엔진 (level-engine)

#### 3.6.1 자동 레벨 산정

- 리뷰 작성 이벤트 수신 시 실시간 퀄리티 점수 재산정
- 레벨 업/다운 조건 달성 시 즉시 반영 및 알림
- 일별 배치: 전체 사용자 퀄리티 점수 재계산

#### 3.6.2 레벨 다운 방지

- 90일간 활동 없을 시 한 단계 강등 경고
- 180일간 활동 없을 시 한 단계 강등 실행

---

### 3.7 검색 (search-service)

#### 3.7.1 통합 검색

- 장소명, 지역, 리뷰 텍스트 풀텍스트 검색
- 자동완성 (장소명 기준)
- 검색 결과 내 필터: 카테고리, 지역, 매니아 평점 기준

#### 3.7.2 위치 기반 검색

- 위경도 + 반경 기반 geo_distance 쿼리
- 지도 뷰에서 현재 화면 범위 내 장소 조회

---

### 3.8 광고 / 상단 노출 (ad-service)

#### 3.8.1 업장 등록

- 업장 운영자가 본인 매장 소유권 인증 후 광고주 등록

#### 3.8.2 상단 노출

- 지역·카테고리 검색 결과 상단 노출 (최대 2개 슬롯)
- 노출 기간 및 예산 설정
- 노출 표시: "광고" 뱃지 명시

#### 3.8.3 광고 효과 리포트 (Post-MVP)

- 노출수, 클릭수, 리뷰 유입수 통계

## 4. 비기능 요구사항

### 4.1 성능

| 항목 | 목표 |
|------|------|
| 장소 검색 응답 | P95 < 300ms |
| 피드 로딩 | P95 < 500ms |
| 리뷰 작성 | P95 < 1s |
| 동시 접속자 | 초기 1,000 CCU, 스케일아웃 대응 |

### 4.2 가용성

- 서비스 목표 가용성: 99.5% (월 기준 약 3.6시간 허용 다운타임)
- 데이터베이스: Multi-AZ 구성

### 4.3 보안

- JWT 기반 인증 (Access Token 1h, Refresh Token 30d)
- 모든 API HTTPS 강제
- 개인정보: 비식별화 처리, GDPR 준수 고려

### 4.4 확장성

- 신규 카테고리 추가 시 코드 변경 최소화 (카테고리 스키마 DB 관리)
- 트래픽 급증 시 개별 서비스 독립 스케일아웃

## 6. 마이크로서비스 구조

### 6.1 서비스 목록

```
yamilog/
├── gateway/                  # Spring Cloud Gateway
├── services/
│   ├── user-service/         # 회원, 레벨 프로필, 팔로우
│   ├── category-service/     # 카테고리 메타, 평가 항목 스키마
│   ├── place-service/        # 장소 등록, 검색, 지도 연동
│   ├── review-service/       # 리뷰 CRUD, 유용성 투표
│   ├── feed-service/         # 팔로우 피드, 카테고리 피드
│   ├── level-engine/         # 매니아 등급 자동 산정
│   ├── search-service/       # Elasticsearch 기반 통합 검색
│   └── ad-service/           # 광고, 상단 노출
├── common/
│   ├── common-domain/        # 공유 도메인 모델, 이벤트 정의
│   └── common-infra/         # 공통 인프라 설정 (Kafka, Security 등)
└── frontend/                 # Next.js 15
```

### 6.2 헥사고날 아키텍처 패키지 구조 (각 서비스 공통)

```
{service}/src/main/java/com/yamilog/{service}/
├── domain/
│   ├── model/                # 도메인 엔티티, 값 객체
│   └── event/                # 도메인 이벤트 정의
├── application/
│   ├── port/
│   │   ├── in/               # UseCase 인터페이스 (Inbound Port)
│   │   └── out/              # Repository, 외부 서비스 인터페이스 (Outbound Port)
│   └── service/              # UseCase 구현체 (Application Service)
└── adapter/
    ├── in/
    │   ├── web/              # REST Controller
    │   └── messaging/        # Kafka Consumer
    └── out/
        ├── persistence/      # JPA / MongoRepository 구현
        ├── messaging/        # Kafka Producer 구현
        └── external/         # 외부 API (지도 등) 클라이언트
```

## 7. 이벤트 플로우

### 7.1 핵심 도메인 이벤트

| 이벤트 | 발행 서비스 | 구독 서비스 | 목적 |
|--------|------------|------------|------|
| `ReviewCreated` | review-service | level-engine, feed-service, search-service | 레벨 재산정, 피드 갱신, 색인 |
| `ReviewUpdated` | review-service | level-engine, search-service | 퀄리티 재산정, 색인 갱신 |
| `LevelChanged` | level-engine | user-service, feed-service | 프로필 업데이트, 레벨업 피드 |
| `PlaceCreated` | place-service | search-service, feed-service | 색인, 신규 장소 피드 |
| `UserFollowed` | user-service | feed-service | 팔로우 피드 갱신 |

### 7.2 리뷰 작성 → 레벨 산정 플로우

```
[사용자] → POST /reviews
         → review-service (저장)
         → Kafka: ReviewCreated
             ├─ level-engine (퀄리티 계산 → 레벨 체크)
             │     └─ Kafka: LevelChanged (레벨 변경 시)
             │           ├─ user-service (프로필 갱신)
             │           └─ feed-service (레벨업 알림 피드)
             ├─ feed-service (팔로워 피드 추가)
             └─ search-service (Elasticsearch 색인)
```

## 8. MVP 범위 및 로드맵

### 8.1 MVP (Phase 1) — 목표: 핵심 루프 검증

| 기능 | 포함 여부 |
|------|----------|
| 소셜 로그인 (Google, Kakao) | ✅ |
| 장소 등록 / 검색 (위치 기반) | ✅ |
| 리뷰 작성 (커피/위스키/와인) | ✅ |
| 레벨 시스템 자동 산정 | ✅ |
| 카테고리 피드 | ✅ |
| 팔로우 피드 | ✅ |
